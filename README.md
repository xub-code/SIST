# SIST: Audio-Text Multimodal Recognition for Alzheimer's Disease

This repository provides the experimental implementation of the SIST model for audio-text multimodal recognition of Alzheimer's disease and related cognitive impairment. The code supports experiments on three datasets: **ADReSS2020**, **ADReSSo2021**, and **NCMMSC2021**, under both the official split protocol and the five-fold cross-validation protocol.

SIST takes speech audio representations and transcript text representations as multimodal inputs. It performs modality-specific representation learning, cross-modal interaction modeling, and post-interaction representation fusion for cognitive status recognition. This repository provides the corresponding training scripts, testing scripts, and checkpoint directories for each dataset under both experimental protocols.

> Note: In this repository, `OS` denotes the official split protocol, and `5CV` denotes five-fold cross-validation. The number of classes and class names should follow the dataset directories and the `class_map` settings in the corresponding scripts.

## 2. Environment Setup

We recommend using Conda to create an isolated Python environment.

```bash
conda create -n sist python=3.8 -y
conda activate sist
```

Install PyTorch according to the CUDA version of your machine. For example, the following command can be used for a CUDA 11.3 environment:

```bash
pip install torch==1.10.0+cu113 torchvision==0.11.1+cu113 \
  --extra-index-url https://download.pytorch.org/whl/cu113
```

Install the remaining dependencies:

```bash
pip install -r requirements.txt
```

If `audio_to_text.py` is used for automatic speech transcription, install the Whisper-related dependencies:

```bash
pip install openai-whisper
pip install opencc-python-reimplemented
```

## 4. Data Organization

This repository contains three dataset directories. Each dataset supports two experimental protocols: the official split and five-fold cross-validation.

### 4.1 Official Split Data

The official split data contain only `train` and `test` subdirectories. There is no `val` directory. The official split directories of the three datasets are organized as follows:

```text
ADReSS2020/
├── train/
└── test/

ADReSSo2021/
├── train/
└── test/

NCMMSC2021/
├── train/
└── test/
```

Each `train` or `test` directory contains class-specific subdirectories. The class names must be consistent with the class mapping defined in the corresponding training and testing scripts. For example:

```text
NCMMSC2021/
├── train/
│   ├── AD/
│   ├── HC/
│   └── MCI/
└── test/
    ├── AD/
    ├── HC/
    └── MCI/
```

For ADReSS2020 and ADReSSo2021, the exact class directories should follow the actual dataset organization and the `class_map` defined in the corresponding scripts.

### 4.2 Five-Fold Cross-Validation Data

The five-fold cross-validation data contain `fold1` to `fold5`. Each fold contains only `train` and `test` subdirectories.

```text
ADReSS2020_5CV/
├── fold1/
│   ├── train/
│   └── test/
├── fold2/
│   ├── train/
│   └── test/
├── fold3/
│   ├── train/
│   └── test/
├── fold4/
│   ├── train/
│   └── test/
└── fold5/
    ├── train/
    └── test/
```

The structures of `ADReSSo2021_5CV/` and `NCMMSC2021_5CV/` are the same as above.

### 4.3 Multimodal Feature Format

The training scripts read pre-extracted `.npy` feature files rather than raw `.wav` or `.txt` files. Audio features and text features should be placed in the same class directory, and their filename bodies should be consistent.

The recommended naming format is as follows:

```text
dataset_directory/
├── train/
│   ├── AD/
│   │   ├── audio_sample001.npy
│   │   ├── text_sample001.npy
│   │   ├── audio_sample002.npy
│   │   └── text_sample002.npy
│   ├── HC/
│   └── MCI/
└── test/
    ├── AD/
    ├── HC/
    └── MCI/
```

`dataset.py` automatically matches the audio and text features of the same sample according to the filename prefixes. For example:

```text
audio_sample001.npy
text_sample001.npy
```

will be treated as one multimodal sample. If a sample has only an audio feature or only a text feature, it will not be used as a valid multimodal sample for training or testing.

## 5. Preprocessing Pipeline

The complete preprocessing and training pipeline is as follows:

```text
Raw audio
  ↓
Audio-to-text transcription, optional
  ↓
Audio feature extraction
  ↓
Text feature extraction
  ↓
Multimodal sample matching
  ↓
Training and testing
```

### 5.1 Audio-to-Text Transcription

If the dataset already provides manual transcripts, this step can be skipped.

`audio_to_text.py` uses Whisper for batch audio transcription. Before running the script, please modify the input directory, output directory, and language setting according to your local data paths.

```bash
python audio_to_text.py
```

For Chinese data, the language can be set as:

```python
language = "zh"
```

For English data, the language can be set as:

```python
language = "en"
```

### 5.2 Audio Feature Extraction

`extract_features_audio.py` is used to extract audio features and save each audio sample as `audio_*.npy`.

```bash
python extract_features_audio.py
```

Before running the script, please check or modify the data path, pretrained audio model path, output path, and feature extraction parameters. The output directory should be consistent with the data directory used by the subsequent training scripts.

### 5.3 Text Feature Extraction

`extract_features_text.py` is used to extract text features and save each text sample as `text_*.npy`.

```bash
python extract_features_text.py
```

English datasets can usually be processed using an English BERT model or another English Transformer encoder. Chinese datasets can usually be processed using a Chinese BERT model or another Chinese Transformer encoder. The audio features and text features should be saved in the same sample directory to ensure correct matching by `dataset.py`.

### 5.4 Five-Fold Dataset Construction

`make_5fold_dataset.py` is used to construct the five-fold cross-validation splits. Before running the script, please check the input directory, output directory, and random seed.

```bash
python make_5fold_dataset.py
```

The generated directory should be organized as follows:

```text
dataset_name_5CV/
├── fold1/
│   ├── train/
│   └── test/
├── fold2/
│   ├── train/
│   └── test/
├── fold3/
│   ├── train/
│   └── test/
├── fold4/
│   ├── train/
│   └── test/
└── fold5/
    ├── train/
    └── test/
```

Note: The five-fold cross-validation scripts in this repository read data from `fold*/train` and `fold*/test`. Therefore, the testing directory inside each fold should not be named `val`.

## 6. Model Files

The model-related files are listed below.

| File | Description |
|---|---|
| `model_audio.py` | Builds the audio modality encoding branch for learning acoustic speech representations. |
| `model_text.py` | Builds the text modality encoding branch for learning semantic transcript representations. |
| `model.py` | Builds the main SIST network for audio-text representation interaction, fusion, and classification. |
| `dataset.py` | Loads audio `.npy` and text `.npy` features, and performs sample matching, sequence padding, and label generation. |

The overall input-output process is summarized as follows:

```text
Audio feature sequence ──> Audio encoder branch ──┐
                                                   ├──> SIST cross-modal fusion module ──> Classification output
Text feature sequence  ──> Text encoder branch  ──┘
```

## 7. Training and Testing

This repository provides official split and five-fold cross-validation scripts for all three datasets. During training and testing, the data directory, class mapping, checkpoint directory, and script name should be kept consistent.

### 7.1 Official Split Experiments

Official split experiments use the `train` and `test` directories of the corresponding dataset.

| Dataset | Training Script | Testing Script | Data Directory | Checkpoint Directory |
|---|---|---|---|---|
| ADReSS2020 | `train_adress_os.py` | `test_adress_os.py` | `ADReSS2020/` | `weights_adress_os/` |
| ADReSSo2021 | `train_adresso_os.py` | `test_adresso_os.py` | `ADReSSo2021/` | `weights_adresso_os/` |
| NCMMSC2021 | `train_ncmmsc_os.py` | `test_ncmmsc_os.py` | `NCMMSC2021/` | `weights_ncmmsc_os/` |

Example commands:

```bash
# ADReSS2020 official split
python train_adress_os.py
python test_adress_os.py

# ADReSSo2021 official split
python train_adresso_os.py
python test_adresso_os.py

# NCMMSC2021 official split
python train_ncmmsc_os.py
python test_ncmmsc_os.py
```

### 7.2 Five-Fold Cross-Validation Experiments

Five-fold cross-validation experiments use `fold1` to `fold5` in the corresponding `_5CV` directory. Each fold contains `train` and `test` subdirectories.

| Dataset | Training Script | Testing Script | Data Directory | Checkpoint Directory |
|---|---|---|---|---|
| ADReSS2020 | `train_adress_cv.py` | `test_adress_cv.py` | `ADReSS2020_5CV/` | `weights_adress_cv/` |
| ADReSSo2021 | `train_adresso_cv.py` | `test_adresso_cv.py` | `ADReSSo2021_5CV/` | `weights_adresso_cv/` |
| NCMMSC2021 | `train_ncmmsc_cv.py` | `test_ncmmsc_cv.py` | `NCMMSC2021_5CV/` | `weights_ncmmsc_cv/` |

Example commands:

```bash
# ADReSS2020 five-fold cross-validation
python train_adress_cv.py
python test_adress_cv.py

# ADReSSo2021 five-fold cross-validation
python train_adresso_cv.py
python test_adresso_cv.py

# NCMMSC2021 five-fold cross-validation
python train_ncmmsc_cv.py
python test_ncmmsc_cv.py
```

## 9. Model Complexity Statistics

`calc_s4_thop.py` is used to compute model complexity statistics, including the number of parameters, MACs, and FLOPs. Before running the script, please confirm that the data path, model configuration, and checkpoint path are consistent with the current experiment.

```bash
python calc_s4_thop.py
```

If the script provides command-line arguments, the data directory, checkpoint path, and output filename can be specified as needed. For example:

```bash
python calc_s4_thop.py \
  --data_root NCMMSC2021 \
  --split test \
  --weights_file weights_ncmmsc_os/best.pth \
  --save_txt ncmmsc_os_complexity.txt
```

## 11. Recommended Running Order

The recommended running order is as follows:

```text
1. Download the datasets, preprocessed features, and model checkpoints from Baidu Netdisk, and extract them into the SIST/ root directory.
2. Prepare the raw audio files and transcripts.
3. Run audio_to_text.py for audio transcription, if needed.
4. Run extract_features_audio.py for audio feature extraction.
5. Run extract_features_text.py for text feature extraction.
6. Check whether audio_*.npy and text_*.npy can be matched one-to-one.
7. Run the train_*.py script corresponding to the selected dataset and protocol.
8. Run the test_*.py script corresponding to the selected dataset and protocol.
9. Run calc_s4_thop.py for model complexity statistics, if needed.
10. Run plot_utils.py or plot_utils_cv.py for experimental visualization, if needed.
```

## 12. Evaluation Metrics

For reporting experimental results, the following metrics are recommended:

```text
Accuracy
Precision
Recall
F1-score
AUC
PR-AUC
```

For five-fold cross-validation experiments, it is recommended to report:

```text
mean ± standard deviation
```

For multi-class classification tasks, please specify whether macro-average, micro-average, or weighted-average metrics are used. For cognitive impairment recognition, macro-average metrics are generally recommended to reduce the influence of class imbalance and majority-class bias.

## 13. Important Notes

1. The official split directories are organized as `train/test`. The five-fold cross-validation directories are organized as `fold1` to `fold5`, and each fold also contains `train/test`.
2. This repository does not use `val` as a fixed directory name. The README and code paths should remain consistent with `train/test`.
3. Audio feature files should use the `audio_` prefix, and text feature files should use the `text_` prefix. The filename body should be identical for matched audio-text pairs.
4. Training scripts, testing scripts, data directories, and checkpoint directories must correspond to each other. For example, `train_adresso_cv.py` should correspond to `ADReSSo2021_5CV/` and `weights_adresso_cv/`.
5. The number of classes may vary across datasets. Please follow the dataset directories and the `class_map` in the corresponding scripts, and do not mix class mappings across datasets.
6. If local pretrained models are used, please modify the model paths in the feature extraction scripts and ensure that the audio and text pretrained models can be loaded correctly.
7. If the five-fold data are re-split, please fix the random seed and report the data splitting protocol in the manuscript.
8. Because the datasets, preprocessed features, and model checkpoints are large, they should be downloaded from Baidu Netdisk and placed in the local repository root directory. They are not recommended to be committed directly to GitHub.
